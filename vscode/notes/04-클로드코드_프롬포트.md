# Claude Code 프롬프트 작성법

## 기본 구조

```text
대상 → 어떤 파일·폴더를 다룰지
목표 → 무엇을 원하는지
제약 → 무엇을 하지 말아야 하는지
검증 → 작업이 제대로 됐는지 어떻게 확인할지
```

## 나쁜 예 / 좋은 예

```text id="i8xg7n"
나쁜 예
"이거 고쳐줘"

좋은 예
"notes/03-클로드코드_권한모드.md 파일에서
Auto 설명 부분에 예시를 하나 추가해줘.
다른 섹션은 수정하지 말고,
수정 후 변경한 부분만 알려줘."
```

### 좋은 예 분해


* **대상:** `notes/03-클로드코드_권한모드.md`
* **목표:** Auto 설명에 예시 하나 추가
* **제약:** 다른 섹션은 수정하지 않음
* **검증/결과:** 수정 후 변경한 부분만 보고

```text id="qkvv9a"
목표  → 예시 하나 추가
대상  → notes/03-클로드코드_권한모드.md
제약  → 다른 섹션 수정 금지
결과  → 변경한 부분만 알려주기
```

나쁜 예는 Claude가 **어떤 파일을, 어떻게, 어디까지 수정해야 하는지 추측해야 함**.


* 대상과 범위가 명확할수록 Claude의 불필요한 추측이 줄어듦

## 범위를 좁히는 표현

```text
~파일만 확인해줘
~는 수정하지 마
~폴더는 열지 마
~까지만 하고 멈춰줘
```

* 익숙하지 않은 프로젝트일수록 범위를 명확히 지정

## 결과 형식 지정

```text
요약만 알려줘
변경한 부분만 알려줘
코드 없이 설명만 해줘
표로 정리해줘
```

## 단계별 요청 vs 한 번에 요청

* **단계별 요청:** 탐색 → 계획 → 수정으로 나눠 진행

  * 큰 작업, 처음 보는 코드에 적합
* **한 번에 요청:** 목표와 제약을 지정해 바로 진행

  * 작고 익숙한 작업에 적합

## 검증 요청

```text
수정한 파일을 알려줘
변경한 부분만 요약해줘
실행해서 오류가 없는지 확인해줘
테스트 결과를 알려줘
```

* Claude가 작업을 완료했다고 해도 실제 변경 범위와 실행 결과를 확인

## 주의점

* `"적당히"`, `"알아서"` 같은 모호한 표현 최소화
* 파일 경로는 가능하면 정확히 명시
* 중요한 조건은 필요하면 다시 명시
* 작업 후 실제 변경 파일과 범위를 확인
